## Do not infer an official preset

Use the current notification to record separate photo and signature requirements. A signature often has a different aspect ratio from a portrait, so fitting both into one crop can distort one of them. The general resizer enforces file-processing limits, not official examination acceptance.

An exam application is a poor place to discover that a photograph was edited to the wrong specification. The safest approach is to separate the administrative question—what this application requires—from the image-editing question—how to make that particular file. This walkthrough explains the second part without pretending to know the current rules for every SSC application. The [SSC photo and signature workspace](/resize-photo-signature-ssc/) displays verified requirements from the official notice, noting that current SSC forms require live photo capture rather than an uploaded portrait.

## Start with the exact application

Open the official notification and the instructions attached to the application you are actually completing. Record the exam name, year or cycle, and the relevant document section. A screenshot of an old tutorial is not a reliable substitute for the current form. If the portal provides an additional upload note beside the field, compare that note with the notification before editing. Resolve a disagreement through the official help channel rather than inventing a compromise.

Make two short records: one for the photograph and one for the signature. For each, record width, height, accepted format, minimum file size and maximum file size when those are specified. Also record content conditions, such as whether the instruction asks for a particular capture process. An ordinary file resizer cannot satisfy a requirement for a different capture method merely by producing a small image.

## Choose originals worth working with

Use the clearest available source. Open it at a useful zoom and inspect the face or the pen strokes before changing anything. Compression can reduce bytes, but it cannot reliably reconstruct a blurred eye, a missing letter or a clipped edge. Keep the source untouched and export a separate working copy. This makes it possible to start again when a crop turns out to be too tight.

Avoid taking a screenshot of a photograph displayed inside another application. Screenshots often include borders and can reduce useful detail. If the source lives on a phone, transfer the actual file when possible. For a signature, inspect the entire mark and its surrounding margin. A small isolated stroke near the edge may be part of the signature rather than unwanted background.

## Crop before chasing kilobytes

Cropping determines what is in the picture; resizing determines how many pixels represent it. Do the crop first. Use the [photo crop workspace](/tools/passport-photo/) with custom dimensions only after reading the applicable instructions. Its name does not make a result compliant with an SSC form, and its generic presets are not an official specification.

Keep the crop proportional to the required output. If you need to change a portrait-shaped source into a different ratio, decide which background area can be removed without cutting required content. Do not unlock the ratio and stretch a face until it fits. For a signature, prefer keeping the full mark with a suitable margin rather than filling every pixel of the box.

## Set dimensions and then check bytes

Use the [pixel resizer](/tools/resize-image-pixels/) when the instructions give exact pixel dimensions. Read the downloaded file’s dimensions rather than assuming the input settings describe every later output. A subsequent size-reduction step can downscale an image when quality changes alone are insufficient. That may create a file under the byte limit but outside the dimension requirement.

The [target-size image tool](/tools/resize-image-kb/) searches JPEG quality and, if necessary, reduces dimensions. Choose a target with a little room below a stated maximum when the portal’s counting convention is unclear. Here the tool counts one KB as 1,024 bytes. Do not enlarge an image merely to satisfy a minimum byte count without understanding whether useful detail is present; additional bytes do not create additional evidence.

## Check the pair as a submission

Open both exported files from the download folder. Check format, dimensions, byte count and visible content separately. Give them clear filenames that distinguish photo from signature and this application from older attempts. If the portal shows a preview, confirm that it displays the latest version. A browser can keep a previously selected file even after you create a new one with a similar name.

Other application fields deserve independent checks. The [age calculator](/calculators/age/) can help compare calendar dates, but it does not interpret an exam’s eligibility rule, cutoff convention or relaxation provisions. Read those from the official instructions. A correctly sized photograph and a plausible age result do not establish eligibility, and the image workspace does not submit the application for you.

## Handle rejection methodically

If an upload fails, copy the exact error message and compare it with the file properties. A format error calls for a format check; a dimensions error calls for a pixel check. Repeatedly compressing the same image without identifying the failed condition can make quality worse while leaving the actual problem untouched. Return to the original when a correction requires a different crop or export format.

Keep the exported pair until the process is finished. Do not overwrite the originals with the portal-sized versions. If an official correction window or support request requires another upload, a clean source gives you more options than a repeatedly compressed miniature.
