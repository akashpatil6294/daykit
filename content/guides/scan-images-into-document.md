A phone can produce a useful document image, but placing that image inside a PDF does not automatically make it a good scan. Capture quality, page completeness, orientation and order all matter. A careful source usually gives you more flexibility when you later need a small attachment.

Begin with the recipient’s document list. Decide which pages are required and whether the requested output is one combined PDF or separate attachments. Avoid creating a single large packet merely because a merge tool makes that easy. The structure should match the application’s fields and instructions.

## Capture a complete page

Place the document so that all required edges and marks are visible. Check for glare, shadows and motion blur before moving to the next page. A bright heading does not prove that faint text near a fold is readable. Inspect the most difficult area of each image while you still have the original document available.

Keep the camera reasonably aligned with the page. Strong perspective can make one end of a line much smaller than the other. Daykit’s image-to-PDF tool fits the supplied image; it does not automatically correct perspective or recover missing corners. If the image is badly skewed, a fresh capture may be more effective than later resizing.

## Prepare the image files before assembly

Use actual image files rather than screenshots of a gallery preview. Screenshots can add interface elements, reduce resolution or include borders. If a phone stores the images as HEIC and you need JPEG inputs, use the [HEIC-to-JPG converter](/tools/heic-to-jpg/) or an appropriate device export. Open a converted sample and inspect its orientation and appearance.

Rotate images into their intended reading orientation before assembly. Name or arrange them so that you can identify their order. A file picker’s selection order is not always intuitive, especially when files have mixed dates or names. The visible list in the tool is the sequence to review before creating the PDF.

## Build the PDF deliberately

Use [images to PDF](/tools/images-to-pdf/) to place one JPG or PNG on each output page. The tool keeps the image ratio and fits it within A4 margins. It places transparency on white and reduces very large images to a bounded working resolution before encoding. These choices make the workflow practical on a phone, but they still require visual review.

The output is image-based. Text selection does not appear simply because the file extension is PDF. If the recipient needs an accessible or searchable document, obtain a suitable original export or use a verified OCR process. Do not present an image-only packet as equivalent to a properly structured digital document.

## Check page order and completeness

Download the assembled result and read it from the first page to the last. Check that no image was included twice and that no page was omitted. Look at the transitions between sections: a declaration should remain associated with the document it explains, and a continuation page should follow its preceding page.

If you already have a PDF with the wrong order, use [reorder/delete pages](/tools/reorder-pdf/) with a numbered keep-list. If you are combining an image-based packet with an existing PDF, use [merge PDFs](/tools/merge-pdf/). Keep in mind that advanced document features and digital signatures should not be assumed to survive page copying.

## Evaluate size after the packet is correct

Only assess compression once the contents and order are settled. Compare the complete PDF’s bytes with the destination’s maximum. If it already fits with good clarity, another reduction may add risk without benefit. Large input photographs do not necessarily imply that the resulting PDF must be unacceptable; measure the actual export.

When a reduction is needed, use the [PDF compressor](/tools/compress-pdf/) and inspect the result. It rasterizes pages and may lower both quality and resolution to reach the target. Review small identifiers and handwritten details carefully. A cleaner capture can sometimes produce a better small output than repeated processing of a noisy source.

## Keep a source set and a submission set

Store the original images separately from the PDF chosen for submission. This makes future corrections possible without photographing the documents again. Use clear version names while comparing outputs, then identify the exact chosen file before opening the upload form. Avoid relying on whichever download happens to appear first in a picker.

After submission, retain the confirmation available through the official process. On a shared device, remove temporary scans and exports when they are no longer needed. Browser-local conversion prevents this tool from uploading the documents, but copies in a download folder remain part of your privacy responsibilities.
